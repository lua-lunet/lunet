# Lunet 的 Talos、Ethos 与無為

[English Documentation](PHILOSOPHY.md)

三个词描述了 Lunet 的用途与行事方式：一位守卫、一种品格、一种无为而治。

## Talos —— 守卫的姿态

Talos 每天绕克里特岛三圈，把敌对船只挡在岛外。Lunet 对你的机器持同样的
态度：**网络被挡在边界之外，而边界就是回环地址（loopback）**。

- `lunet-run` 拒绝把监听器绑定到 `127.0.0.1`、`::1` 或 Unix socket 以外的
  任何地址。默认状态下不存在远程安全漏洞。
- 打开边界是一个明确、可闻的行为：
  `--dangerously-skip-loopback-restriction`。这个标志故意写得很长，
  就是让你郑重其事地说出口。
- 当你确实要暴露服务时，请在前面放一个久经考验的 sidecar —— nginx、
  OpenResty、Caddy、Envoy；选择权属于管理员，而不是 Lunet。这是 qmail
  的教训：与网络对话的进程应当小巧、沉闷、戒备森严，而且它不应该是你的
  应用。协议拆分攻击（protocol smashing）会死在代理层，而不是你的 Lua
  协程里。
- 存在一个合理的例外：在私有客户端网络中，如果唯一入口是一个能清洗畸形
  流量、吸收 DDoS 的加固云代理，那么绑定所有网卡可以是安全的。Lunet 不
  禁止这样做；Lunet 禁止的是*在不知不觉中*这样做。

## Ethos —— 品格

- **稳定优先。** Lunet 的依赖 —— LuaJIT、libuv、zlib —— 都是拥有长期
  发行版支持的成熟库。没有 npm 或 pip 式的折腾，也没有为你从未要求的库
  每周打安全补丁的跑步机。
- **发布版即产品。** 用 xmake 从源码构建是*开发* Lunet 的好方式，但要求
  每个用户在每个 OS 上自行拼装工具链，只会让一个项目零用户。更糟的是：
  只用一个 OS 的维护者无法承诺源码构建在别的平台上可行 —— 各平台库的
  细微漂移会让“在我机器上能用”成为默认的失败模式。因此由 CI 为 Linux、
  macOS 和 Windows 构建二进制，CI 发布什么，我们就担保什么。
- **以 Lua 为核心。** 其他运行时忙着打生态战争、在语言之间移植自己的
   internals。Lua 用三十年做到了小巧、稳定、可嵌入。Lunet 采纳大型生态
  的*便利设施* —— nginx 风格的共享字典（`lnt_shared`）、高速 JSON
  （`jsonic`）、类型化 Lua 绑定（teal，计划中）—— 但不引入它们的动荡。
  大停滞时代已经结束；答案不是更大的运行时，而是更小、更守规矩的运行时。
- **诚实的接口。** 公开的 C API（`include/lunet.h`）把头文件当作契约
  文档：每进程一个运行时、一次运行、非线程安全。Lunet 做不到的事，
  它会明说。

## 無為（wu wei）—— 无为而治

无为，是不强求而事成。Lunet 的版本是：以减法为功能。

- **只构建你需要的。** 一个数据库驱动，而不是三个。没有未使用的依赖、
  没有死重、没有你从不使用的攻击面。没有链接进来的代码，既无法被利用，
  也不会出故障。
- **小即能力。** 一个 Lunet MCP 服务器空闲时只占个位数 MB 内存，磁盘
  占用只是 Node、Bun 或 Python 同类方案的零头（见 README 中的对比表）。
  小东西启动快、审计快、哪儿都放得下。
- **运行时不挡路。** 每连接一协程、一个事件循环、朴素的 Lua。你与
  socket 之间没有框架魔法。

## 三种开发者体验

同一引擎服务三类用户；请选择属于你的那一行。

| 路径 | 适合谁 | 需要什么 | 从这里开始 |
|------|--------|----------|------------|
| **运行 Lua** | 你写 Lua 应用；不想碰 C 工具链 | 对应 OS 的发布压缩包 | [发布页](https://github.com/lua-lunet/lunet/releases) |
| **打包一体机** | 你要交付单一自包含可执行文件（你的 `main()` + Lunet + 你的应用），而用户机器上什么都没有 | 发布版 SDK + 一个 C 编译器 | [EMBEDDING-CN.md](EMBEDDING-CN.md) |
| **hack 核心** | 你开发 Lunet 本身，或想要最小化功能构建 | xmake + 系统开发库 | [XMAKE_INTEGRATION-CN.md](XMAKE_INTEGRATION-CN.md) |

## 起源：微型 localhost MCP 服务器

Lunet 最初的用途是编写**微型本地 MCP 服务器** —— 运行在 LLM 客户端旁、
回环地址上的 Model Context Protocol 工具：空闲时只占几 MB，瞬间启动。
这仍是首页用例与设计中心：默认回环（Talos）、服务器推送事件（SSE）作为
一等传输、用于调用真实 API 的出站 HTTPS 客户端，以及把成果变成单个自
包含 `.run` 可执行文件的嵌入模式。规范示例见
`examples/mcp_openalex_sse/`。
