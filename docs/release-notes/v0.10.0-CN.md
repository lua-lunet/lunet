- **宿主应用终止现在是运行时的一等契约 —— 主动停止、排水点与后排水冲洗钩子。** 运行中的应用可以自行请求终止：从 Lua 调用 `lunet.stop()`，或宿主在 `run_file` / `run_embedded` 阻塞于运行时线程时从 C 调用 `lunet_runtime_request_stop()` —— 这是运行时唯一线程安全的调用，经由预先布设（且被 uv_unref，因此永远不会钉住事件循环）的 `uv_async` 送达。事件循环立即停止接收新工作；重复请求是无副作用的空操作；循环停止时仍处于挂起状态的工作被安全放弃（悬停中的睡眠定时器不再触发、其协程永远不再被恢复，与出站写入的「安全放弃」规则一致）。
- **具备持久化级语义的后排水钩子（`lunet.on_stop(fn)`）。** 注册的回调在排水点恰好运行一次：`uv_run` 已返回且尚无任何句柄被关闭，此时内存中的状态即最终状态 —— 这正是宿主写入 WAL 并记录超级块 `flushed` 标记的安全点。回调中只做同步工作：循环已不再驱动任何内容，回调内的异步调用无法推进。钩子错误会输出到 stderr，且不会跳过 teardown；回调里再次调用 `lunet.stop()` 是无副作用的空操作。
- **干净的 teardown，带检验的 `uv_loop_close`。** 回调之后，`uv_walk` 通过模块感知的关闭路径关闭所有剩余句柄（socket 监听器/连接 —— 唤醒挂起的等待者、已绑定的 UDP 套接字、signal 等待、以及未触发的睡眠定时器），并清空关闭回调（同时重扫排水期间新产生的句柄）；`uv_loop_close` 保留既有的受检失败报告（绝不静默忽略）—— 失败的运行或从未开始的运行也不会遗留 stop-wakeup 句柄。
- **宿主构建的生命周期：**事件循环启动前为 `running`；请求终止时为 `stopping`；后排水钩子内部为 `flushed`。下次启动时，`flushed` 表示上一次进程干净终止；任何更早的结束状态都说明进程在关机中途死亡，必须重放 WAL。参见 `docs/EMBEDDING-CN.md`（英文版 `docs/EMBEDDING.md`），LuaCATS 注解（`types/lunet.lua`）与 Teal 对等（`types/lunet.d.tl`）同步提供。
- **测试：**红-绿 —— `test/stop_and_drain.lua` 驱动每个平台的 `stress` 套件（标记文件钉住「钩子仅一次」的时序与 teardown 遍历中 accept 等待者的唤醒），`sdk-api-test` 钉住 C 层契约，包括 NULL 参数矩阵与运行结束后请求停止为空操作。
