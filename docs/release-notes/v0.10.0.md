- **Host-app termination is now a first-class runtime contract — a deliberate stop, a drain point, and a post-drain flush hook.** A running application can request termination itself with `lunet.stop()` from Lua, or a host can call `lunet_runtime_request_stop()` from C while `run_file` / `run_embedded` blocks on the runtime thread — the one thread-safe runtime call, delivered through a pre-armed (and unreferenced, so never loop-pinning) `uv_async`. The event loop stops taking new work immediately; repeat requests are safe no-ops; whatever is still parked when the loop is stopped is abandoned safely (a pending sleep timer never fires again and its coroutine is never resumed, mirroring the outbound-write safe-abandon rule).
- **A post-drain hook with persistence-grade semantics (`lunet.on_stop(fn)`).** The registered callback fires exactly once at the drain point: `uv_run` has returned and no handle has been closed yet, so the state in memory is the state — the safe point where a host writes its WAL and records the superblock `flushed` flag. Synchronous work only here: the loop is not driving anything, so async calls inside the callback cannot progress. Hook errors are reported to stderr and cannot skip the teardown; a hook that calls `lunet.stop()` again is a no-op.
- **Clean teardown with checked `uv_loop_close`.** After the hook, `uv_walk` closes every remaining handle through module-aware close paths (socket listeners/connections — waking parked waiters, bound UDP sockets, signal waits, and in-flight sleep timers), close callbacks are drained with a re-sweep for handles created during the drain, and `uv_loop_close` keeps its existing checked (never silently ignored) failure reporting — a failed run or a never-started run cannot strand the stop-wakeup handle either.
- **Lifecycle the host builds on:** `running` before the loop starts, `stopping` when termination is requested, `flushed` inside the post-drain hook. On the next start, `flushed` means the previous process ended cleanly; anything earlier means it died mid-shutdown and the WAL must be replayed. Documented in `docs/EMBEDDING.md` / `-CN.md` with LuaCATS annotations (`types/lunet.lua`) and Teal parity (`types/lunet.d.tl`).
- **Tests:** red-green — `test/stop_and_drain.lua` drives the `stress` suite on every platform (the marker file pins hook-once ordering plus the accept-waiter wake during the walk), and `sdk-api-test` pins the C contract including NULL-argument matrix and a post-run no-op stop request.
