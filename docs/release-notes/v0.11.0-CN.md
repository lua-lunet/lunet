- **sqlite3：`open` 返回两个连接 —— `(rw, ro, err)`。** `rw` 与从前一样是读写
  连接（worker 池）；`ro` 是以 `SQLITE_OPEN_READONLY` 打开的第二个连接，其上的
  查询与执行在循环线程内联运行——不经 worker、不 yield。WAL 模式下读者与唯一
  的写者互不阻塞；一次固定 API 的读密集负载按此路由实测 p95 比把所有语句挤进
  单个池化句柄快约 4 倍，且 `SQLITE_BUSY` 事件为零（见
  [twelve-dollar-server-challenge](https://github.com/lua-lunet/twelve-dollar-server-challenge)
  以及新的性能模型页 `SQLITE.md` / `SQLITE-CN.md`，随 sqlite3 驱动目录与压缩包
  发布）。路由是消费者在构建期拥有的正确性：误路由到 `ro` 的写在 `step` 阶段
  响亮失败并返回 `SQLITE_READONLY`，绝不可能静默提交。打开失败时两个句柄均为
  `nil`，错误是第三个返回值——sqlite3 特有形态；网络驱动保持 `(conn, err)`。
  拆分需要文件路径（`:memory:` 无法拆分）。
- **sqlite3：不提供池化——正确的形状同时也是轻松的形状。** 单写路径就是设计
  本身；想更快，就把读交给 `ro`，永远不要靠加宽池。驱动现在按它期望被使用的
  方式打开：`open(config)` 按路径字符串缓存 `(rw, ro)` 对（重复打开返回同一
  对——没有重复开库的浪费），`destroy(path)` 关闭两者并清除缓存项，
  `open_raw(config)` 总是打开全新一对，供自行管理生命周期的调用者使用。二进
  制模块注册为 `lunet.sqlite3core`，只管异步 I/O；Lua 加载器
  （`lunet/sqlite3.lua`，随二进制发布）持有缓存策略。
- **postgres 与 mysql：`pool_size`（默认 1）是正经特性。** 返回句柄背后的 N
  个服务器连接，一条语句 → 一个成员，轮转选取；`close` 关闭全部成员。这两
  个服务器本就服务并发的客户端连接，而此前这些驱动从未附带任何池机制、模式或
  示例。`postgres_tx`/`mysql_tx` 要求默认值（事务属于连接）。
- **新文档：覆盖类型提示**（`docs/TYPE_OVERRIDES.md` / `TYPE_OVERRIDES-CN.md`，
  随压缩包发布）——在 LuaCATS 与 Teal 中用一行就地修正错误提示、而不重构自己
  代码的配方。
