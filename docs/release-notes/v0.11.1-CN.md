- **v0.11.1 取代已撤回的 v0.11.0。** v0.11.0 的 tag 与 release 已被维护者
  撤回并删除（见 `docs/release-notes/v0.11.0-CN.md`）；下文全部要点均随本
  版本发布，并新增 sqlite3 打开契约。
- **sqlite3：打开契约现已显式化。** `open({ path })` 以 `READWRITE`（不含
  `CREATE`）打开一个已存在的、已建好的文件 —— 文件缺失是响亮的错误，日志
  模式绝不被触碰。`open({ path, create = "WAL" })` 以 `READWRITE|CREATE`
  打开并在写连接上执行 `PRAGMA journal_mode=WAL`，检查该 pragma 的返回
  字符串（失败时返回旧模式而非报错），结果不是 `"wal"` 就响亮地使打开失败
  —— 对已是 WAL 的文件幂等。`open({ path, create = "NORMAL" })` 以
  `READWRITE|CREATE` 打开，日志模式不触碰。
- **sqlite3：知情用户的透传项。** `busy_timeout`（毫秒）、`foreign_keys`
  （布尔）、`synchronous`（`"OFF"` | `"NORMAL"` | `"FULL"`）会在返回前应用
  到两个连接上。它们按连接生效、此后最后写入者获胜 —— `db.exec(handle,
  "PRAGMA …")` 可覆盖任一句柄。
- **sqlite3：`:memory:` 是单元测试替身。** `open({ path = ":memory:" })`
  返回同一个连接作为两个句柄；`create` 被忽略，且不做只读强制；该连接永不
  缓存。
- **sqlite3 文档与示例写明契约。** `SQLITE.md` / `SQLITE-CN.md` 载有打开
  契约小节与只读警告横幅（只读连接在 loop 线程上内联执行，可能拖住主
  loop；拿不准就用读写连接并阅读 SQLite 文档）；示例 03 使用
  `create = "WAL"`，并在首个只读使用处重复该警告。
- **sqlite3：`open` 返回两个连接 —— `(rw, ro, err)`。** `rw` 是和从前一样
  的读写连接（工作线程池）；`ro` 是第二个连接，以 `SQLITE_OPEN_READONLY`
  打开，其查询与 exec 在 loop 线程上内联执行 —— 不进工作线程、不 yield。
  WAL 模式下读者与单一写者互不争用；按此路由的固定 API 读密集负载实测 p95
  比把所有语句都走单个池化句柄好约 4 倍，且 `SQLITE_BUSY` 事件为零（见
  [twelve-dollar-server-challenge](https://github.com/lua-lunet/twelve-dollar-server-challenge)
  与新的性能模型页 `SQLITE.md` / `SQLITE-CN.md`，随 sqlite3 驱动目录与
  压缩包一同发布）。路由是构建期正确性，由使用方负责：误路由到 `ro` 的写
  会在 step 处以 `SQLITE_READONLY` 响亮失败，绝不可能静默提交。打开失败时
  两个句柄均为 `nil`，错误是第三个返回值 —— 这是 sqlite3 特有的形状；网络
  驱动保持 `(conn, err)`。该拆分需要文件路径（`:memory:` 无法拆分）。
- **sqlite3：不做池化 —— 正确的形状同时也是省事的形状。** 单一写路径就是
  设计本身；要更快，把读路由给 `ro`，绝不扩池。驱动现在按它期望被使用的
  方式打开：`open(config)` 以路径字符串为键缓存 `(rw, ro)` 对（重复 open
  返回同一对 —— 没有重复打开的浪费），`destroy(path)` 关闭两者并清除条
  目，`open_raw(config)` 则总是打开全新一对，供自行管理生命周期的调用者使
  用。二进制模块注册为 `lunet.sqlite3core`，只负责异步 I/O；Lua 加载器
  （`lunet/sqlite3.lua`，随包附送）掌握缓存策略。
- **postgres 与 mysql：`pool_size`（默认 1）是真实特性。** 返回的句柄背后
  是 N 个服务器连接，一条语句 → 一个成员，轮转调度；`close` 关闭全部成
  员。这类服务器本就服务并发客户端连接，而这些驱动此前从未发布过任何池机
  制、模式或示例。`postgres_tx`/`mysql_tx` 要求使用默认值（事务属于单个连
  接）。
- **新文档：覆写类型标注**（`docs/TYPE_OVERRIDES.md` /
  `TYPE_OVERRIDES-CN.md`，随压缩包发布）—— 不重构代码、一行修掉 LuaCATS
  与 Teal 中错误类型标注的速查配方。
- **sodium：base64 编解码改用链接库。** `lunet.sodium.base64_encode(data,
  variant)` / `base64_decode(data, variant)` 直接绑定 PAXE cdylib 内已携带
  的 libsodium base64 实现 —— 并提供四个变体常量
  （`BASE64_VARIANT_ORIGINAL`、`..._NO_PADDING`、`..._URLSAFE`、
  `..._URLSAFE_NO_PADDING`）。此前手工重写 base64 的下游代码可以退役了。
- **socket：默认开启 TCP_NODELAY。** `accept` 与 `connect` 建立的 TCP 套接
  字默认启用 `TCP_NODELAY`（关闭 Nagle 算法 —— 小包请求/响应保形）；
  `socket.set_nodelay(handle, enabled)` 可按句柄控制（unix 套接字拒绝）。
