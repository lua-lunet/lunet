## Highlights

- **sqlite3: a precise `open` contract.** Without `create=`, `open` requires
  an existing, provisioned database file — a missing file is a loud error and
  the journal mode is never touched. Passing `create = "WAL"` lets the driver
  create the file and set the sticky `journal_mode=WAL` in one act (the
  pragma's return value is checked; a filesystem that cannot host WAL fails
  the open loudly); `create = "NORMAL"` creates the file and leaves the
  journal mode at the SQLite default. Informed-user passthroughs —
  `busy_timeout` (ms), `foreign_keys`, `synchronous` — are applied to both
  connections at open and stay per-connection afterwards (last write wins:
  `db.exec(handle, "PRAGMA …")` overrides either handle). `{ path =
  ":memory:" }` is the unit-test swap: one connection returned as both
  handles, read-only not enforced there, never cached. The read-only
  connection runs **inline on the loop thread** — no background thread, no
  yield: under some workloads that is peak performance, it depends entirely
  on your workload and SQLite version, and **if in doubt, do not use the
  read-only connection — send everything down the read-write connection**
  (full warning and contract: `SQLITE.md` / `SQLITE-CN.md`).
- **sqlite3: `open` returns two connections — `(rw, ro, err)`.** `rw` is the
  read-write connection as before (worker pool); `ro` is a second connection
  opened `SQLITE_OPEN_READONLY` whose queries and execs run inline on the
  loop thread — no worker hop, no yield. In WAL mode readers never contend
  with the single writer; a fixed-API read-heavy workload routed this way
  measured ~4x better p95 than routing every statement through one pooled
  handle, with zero `SQLITE_BUSY` events (see
  [twelve-dollar-server-challenge](https://github.com/lua-lunet/twelve-dollar-server-challenge)
  and the performance model page `SQLITE.md` / `SQLITE-CN.md`, shipped in
  the sqlite3 driver folder and the archive). Routing is build-time
  correctness the consumer owns: a mis-routed write on `ro` fails loudly at
  step with `SQLITE_READONLY` and can never commit silently. On open
  failure both handles are `nil` and the error is the third return — a
  sqlite3-specific shape; the network drivers keep `(conn, err)`.
- **sqlite3: no pooling — the right shape is also the easy shape.** The
  single write path IS the design; to go faster, route reads to `ro`,
  never widen a pool. `open(config)` caches the `(rw, ro)` pair keyed on
  the path string (a repeat open returns the same pair — no double-open
  waste), `destroy(path)` closes both and clears the entry, and
  `open_raw(config)` always opens a fresh pair for callers who manage their
  own lifetimes. The binary module registers as `lunet.sqlite3core` and
  owns only the async I/O; the Lua loader (`lunet/sqlite3.lua`, shipped
  beside it) owns the cache policy.
- **postgres and mysql: `pool_size` (default 1) is a real feature.** N
  server connections behind the returned handle, one statement → one
  member, round-robin; `close` closes all members. These servers serve
  concurrent client connections, and no pool machinery, pattern, or sample
  ever shipped with these drivers before. `postgres_tx`/`mysql_tx` require
  the default (a transaction belongs to the connection).
- **New documentation: Overriding a Type Hint** (`docs/TYPE_OVERRIDES.md` /
  `TYPE_OVERRIDES-CN.md`, shipped in the archive) — the one-line recipes for
  spot-fixing a wrong hint in LuaCATS and Teal without restructuring your
  code.
- **sodium: base64 encode/decode from the linked library.**
  `lunet.sodium.base64_encode(data, variant)` / `base64_decode(data, variant)`
  bind the libsodium base64 implementation already shipped inside the PAXE
  cdylib — with the four variant constants
  (`BASE64_VARIANT_ORIGINAL`, `..._NO_PADDING`, `..._URLSAFE`,
  `..._URLSAFE_NO_PADDING`). Downstream code that was re-implementing base64
  by hand can retire it.
- **socket: TCP_NODELAY on by default.** TCP sockets from `accept` and
  `connect` start with `TCP_NODELAY` enabled (Nagle's algorithm off — small
  request/response traffic keeps its shape); `socket.set_nodelay(handle,
  enabled)` controls it per handle (unix sockets refuse).
