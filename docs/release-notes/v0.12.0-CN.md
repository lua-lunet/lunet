## 要点


- **三个数据库驱动：显式预编译语句。** `stmt, err = db.prepare(handle, sql)`
  把各家厂商自己的复用机制暴露出来——SQLite 的 reset + 重绑定、保有的
  `MYSQL_STMT`、libpq 的 `PQprepare` / `PQexecPrepared`——配合
  `stmt:query(...)` / `stmt:exec(...)` 的每次调用参数绑定，以及
  `stmt:close()`。没有透明缓存、没有淘汰策略：语句值不值得准备由调用者决
  定（琐碎语句毫无收益；复杂或高频率的可能有——读 SQLite 文档自己判断；
  这里没有任何魔法）。池化句柄要求默认 `pool_size = 1`（语句属于它的连接，
  正如事务属于它的连接）；对同一条语句的第二个并发调用响亮失败（"statement
  is busy"）；关闭后使用是响亮的；sqlite3 只读句柄上的写语句在 prepare 阶
  段即被拒绝。预编译语句见 `examples/10_db_prepared.lua` 与各驱动文档中的
  新章节。
- **postgres 与 mysql：open 透传。** `connect_timeout`（两者）与 `sslmode`
  （postgres，对 libpq 取值做白名单）加入 open 契约的惯例：设置在 open 时
  声明、响亮校验、厂商默认值绝不被驱动覆盖。与 `charset` 一并记载于各驱动
  的 README。
- **sqlite3：精确的 `open` 契约。** 不传 `create=` 时，`open` 要求文件已由
  部署方准备好——文件缺失是响亮的错误，且绝不触碰日志模式。传
  `create = "WAL"` 让驱动一步完成建文件并设上持久的 `journal_mode=WAL`
  （检查 pragma 的返回值；文件系统承载不了 WAL 时 open 响亮失败）；
  `create = "NORMAL"` 建文件、日志模式保持 SQLite 默认。知情用户透传项——
  `busy_timeout`（毫秒）、`foreign_keys`、`synchronous`——在 open 时作用于
  两个连接，此后是每连接、后写者赢（`db.exec(handle, "PRAGMA …")` 可覆盖任
  一句柄）。`{ path = ":memory:" }` 是单元测试交换：一个连接充当两个句柄，
  那里不强制只读，且永不缓存。只读连接在**循环线程内联运行**——没有后台
  线程、不发生 yield：某些负载下这就是峰值性能，是否成立完全取决于你的负
  载和 SQLite 版本；**有疑问就不要用只读连接，全部走读写连接**（完整警告与
  契约见 `SQLITE-CN.md` / `SQLITE.md`）。
- **sqlite3：`open` 返回两个连接 —— `(rw, ro, err)`。** `rw` 与从前一样是读
  写连接（worker 池）；`ro` 是以 `SQLITE_OPEN_READONLY` 打开的第二个连接，
  其上的查询与执行在循环线程内联运行——不经 worker、不 yield。WAL 模式下
  读者与唯一的写者互不阻塞；一次固定 API 的读密集负载按此路由实测 p95 比
  把所有语句挤进单个池化句柄快约 4 倍，且 `SQLITE_BUSY` 事件为零（见
  [twelve-dollar-server-challenge](https://github.com/lua-lunet/twelve-dollar-server-challenge)
  以及性能模型页 `SQLITE-CN.md` / `SQLITE.md`，随 sqlite3 驱动目录与压缩包
  发布）。路由是消费者在构建期拥有的正确性：误路由到 `ro` 的写在 `step` 阶
  段响亮失败并返回 `SQLITE_READONLY`，绝不可能静默提交。打开失败时两个句柄
  均为 `nil`，错误是第三个返回值——sqlite3 特有形态；网络驱动保持
  `(conn, err)`。
- **sqlite3：不提供池化——正确的形状同时也是轻松的形状。** 单写路径就是设
  计本身；想更快，就把读交给 `ro`，永远不要靠加宽池。`open(config)` 按路径
  字符串缓存 `(rw, ro)` 对（重复打开返回同一对——没有重复开库的浪费），
  `destroy(path)` 关闭两者并清除缓存项，`open_raw(config)` 总是打开全新一
  对，供自行管理生命周期的调用者使用。二进制模块注册为 `lunet.sqlite3core`，
  只管异步 I/O；Lua 加载器（`lunet/sqlite3.lua`，随二进制发布）持有缓存策
  略。
- **postgres 与 mysql：`pool_size`（默认 1）是正经特性。** 返回句柄背后的 N
  个服务器连接，一条语句 → 一个成员，轮转选取；`close` 关闭全部成员。这两
  个服务器本就服务并发的客户端连接，而此前这些驱动从未附带任何池机制、模式
  或示例。`postgres_tx`/`mysql_tx` 要求默认值（事务属于连接）。
- **新文档：覆盖类型提示**（`docs/TYPE_OVERRIDES-CN.md` / `TYPE_OVERRIDES.md`，
  随压缩包发布）——在 LuaCATS 与 Teal 中用一行就地修正错误提示、而不重构自
  己代码的配方。
- **sodium：base64 编解码来自链接库。** `lunet.sodium.base64_encode(data,
  variant)` / `base64_decode(data, variant)` 绑定 PAXE cdylib 里本来就带有的
  libsodium base64 实现——附四个变体常量（`BASE64_VARIANT_ORIGINAL`、
  `..._NO_PADDING`、`..._URLSAFE`、`..._URLSAFE_NO_PADDING`）。此前自己手写
  base64 的下游代码可以退休了。
- **socket：默认开启 TCP_NODELAY。** 经 `accept` 与 `connect` 得到的 TCP 套
  接字默认启用 `TCP_NODELAY`（关闭 Nagle——小请求/响应流量保持原形）；针对
  单个句柄可用 `socket.set_nodelay(handle, enabled)` 控制（unix 套接字拒绝
  此设置）。
