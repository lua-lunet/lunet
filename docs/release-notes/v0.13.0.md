## Highlights

- **New extension: `ext/http` — the HTTP handling every app was re-inventing.**
  `lunet.http` (keep-alive request framing, JSON responses, error shapes),
  `lunet.http_context` (the request/response context), and
  `lunet.http_router` (method+pattern routing with `:param` captures, route
  registration on require, a before-dispatch middleware chain via
  `router.use(fn)`, and opt-in CORS — off by default) — pure Lua over
  `lunet.socket`, with the demo `examples/08_http.lua` (an HTTP server with
  `lnt_shared` counters as a trivially contrived kv store — GET reads, POST
  increments, PATCH adjusts). The old `08_lnt_shared.lua` is subsumed. Full
  reference: `docs/HTTP.md` / `HTTP-CN.md`.
- **New extension: `ext/security` — crypto and JWT over the linked libsodium.**
  `require("lunet.security")` returns `crypto` (HMAC-SHA-256 sign/verify with
  constant-time comparison, base64url helpers) and `jwt` (HS256
  encode/decode/verify: type-checked header and payload, `exp` enforced,
  named errors). Built on the existing `lunet.sodium` and `lunet.jsonic`
  surfaces — no new dependencies; ships in the archives. Full reference:
  `docs/SECURITY.md` / `SECURITY-CN.md`.
- **The demo fleet gets its write-up.** `examples/realworld/README.md` /
  `README-CN.md` now states the philosophy (no kitchen sink — the demos
  demonstrate the full range anyway) and carries a table of the demo apps —
  the twelve-dollar-server-challenge submission (with the measured resident
  set: ~4 MB RSS for the running feed server on a dev loop; the challenge's
  own bench measured 18 MB at 2,500 concurrent virtual users), realworld-lua,
  lunet-mcp-sse (overhead: 171 MB image / 7 MB runtime), lunet-backproxy's
  DMZ pattern, and the in-repo `mcp_openalex_sse` demo — plus the index of
  the demo files that ship in-tree.
- **One spec per extension.** `spec/jsonic_spec.lua` and
  `spec/lnt_shared_spec.lua` backfilled — every extension module now has a
  spec file to its name, and the busted suite doubled (222 checks green).
