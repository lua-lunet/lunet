- ext/http: the parser caps are edge-aligned and overridable. `MAX_HEADER_BYTES` moves 16 KiB → 32 KiB — nginx's default `large_client_header_buffers 4 8k` section total — so a conforming edge always answers first and lunet is never the strictest link (never the visible 431 for a request the edge accepted). All three caps (request line 8 KiB, header section 32 KiB, body 1 MiB) now live in `ext/http/http_caps.lua` — pure Lua, shipped beside `http.lua` in every archive, editable without a rebuild — and are overridable at build time via the new `--lunet_http_request_line_max` / `--lunet_http_header_max` / `--lunet_http_body_max` options, which regenerate the staged caps file; unset options keep the file's defaults. An operator fronting Envoy, Traefik, HAProxy, or Caddy aligns lunet to their edge's numbers instead of nginx's.
- The security architecture document is now a design discussion around the edge: the illustration aside (nginx is named as a common example; OpenResty, Envoy, and many other excellent products exist), what a protocol-aware edge does — TLS termination, adapting protocols above HTTP/1.1, holding connection keep-alives over the internet, and buffering the full request before forwarding, which absorbs single-byte drip and fragmented-framing attacks (stated from the nginx documentation, with the 414/400/408 mechanics) — the Unix-socket lockdown story (the edge is the only process bound to the network; lunet never binds a network interface), an always-read-the-latest-documentation statement, and the author's opinion on conservative edge choices.
