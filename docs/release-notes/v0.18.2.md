- The HTTP parser is now proven by a fuzz gate, not just by fixtures. The seeded corpus fuzzer over `read_request` grew structure-aware mutators (method, version, Content-Length value, and header-name token rewrites) alongside the byte-level mutators, so the fuzzer explores the parser's decisions, not just its byte handling. The gate asserts rejection-site coverage: every rejection records the parser's error message, and the full reachable-site set must fire across the seeded runs - an uncovered site is a corpus gap, not a success. Cap-boundary fixtures are generated from the live caps values (they follow an override of the caps file): a request at each cap parses, one byte past rejects with the documented status (request line 414, header section 431, body 413). A differential classifier - an independent, minimal reimplementation of the framing contract sharing no code with the parser - replays the corpus and the fixtures; a classification disagreement between it and the parser is the finding. The committed corpus never shrinks: the gate pins a floor on the seed count.
- A nightly fuzz leg explores beyond the fixed per-push budget: a scheduled workflow builds the ASan + easy-memory instrumented runtime and runs the fuzz driver through it with a wall-clock seed (printed for deterministic replay) and a 50000-iteration budget, so oversize allocations and RSS misbehaviour count as findings. The per-push gate stays fixed-budget and deterministic. Suite grew from 324 to 334 assertions.
- CI now proves the release hardening flags on every platform instead of only applying them. A new `xmake verify-hardening` task asserts on the built release binaries what the security runbook previously documented as manual commands only: on Linux, `lunet-run` is PIE (`ET_DYN`), references `__stack_chk_fail`, and carries fortified `__*_chk` symbols; on macOS, the PIE flag and the stack-protector reference; on Windows, DYNAMICBASE and the `/GS` security cookie (dumpbin via vswhere). Every shipped shared module - the core runtime, the SDK library, sqlite3, mysql, postgres, httpc - is checked for the stack protector, closing the question of whether the flag reaches every C target. The build workflow runs the task on all four platform legs right after the build; a missing flag fails the build.
