The 0.18 series in one release: this point release carries everything the
0.18 line shipped, and it is the only 0.18 release kept published.

## Highlights

### Database drivers (0.18.0)

- mysql.open gains open-time TLS passthrough, mirroring the postgres driver's sslmode design: `ssl_ca`, `ssl_capath`, `ssl_cert`, `ssl_key`, `ssl_cipher`, `ssl_crl`, `ssl_crlpath`, `tls_version`, plus `ssl_mode` (mysqlclient) and `ssl_verify_server_cert` (libmariadb). Unset keys leave the vendor library default untouched; wrong types and non-whitelisted values fail loudly at open time.
- The mysql client-library floor is raised to the supported LTS client lines: mysqlclient >= 8.0 (Oracle) and libmariadb >= 3.4 (MariaDB Connector/C), enforced at compile time with a named error. The raise prunes the removed legacy option surface (`MYSQL_OPT_SSL_VERIFY_SERVER_CERT` and `MYSQL_OPT_SSL_ENFORCE`) instead of cutting off older servers, and the libmariadb floor checks the connector package version, not the server version the same macro reports in server-bundled builds.
- Eight per-extension build flags (`lunet_ext_paxe`, `lunet_ext_crypto`, `lunet_ext_lnt_shared`, `lunet_ext_jsonic`, `lunet_ext_sqlite3`, `lunet_ext_mysql`, `lunet_ext_postgres`, `lunet_ext_httpc`), all default ON, gate each extension's build and its specs in the test chain — a machine without cargo, or a build that only wants the database drivers, can exclude the rest without touching CI, where every flag stays ON.

### The edge-aligned HTTP parser (0.18.1)

- ext/http: the parser caps are edge-aligned and overridable. `MAX_HEADER_BYTES` moved 16 KiB → 32 KiB — nginx's default `large_client_header_buffers 4 8k` section total — so a conforming edge always answers first and lunet is never the strictest link. All three caps (request line 8 KiB, header section 32 KiB, body 1 MiB) live in `ext/http/http_caps.lua` — pure Lua, shipped beside `http.lua` in every archive, editable without a rebuild — and are overridable at build time via the `--lunet_http_request_line_max` / `--lunet_http_header_max` / `--lunet_http_body_max` options, which regenerate the staged caps file. An operator fronting Envoy, Traefik, HAProxy, or Caddy aligns lunet to their edge's numbers instead of nginx's.
- The security architecture document is now a design discussion around the edge: what a protocol-aware edge does (TLS termination, adapting protocols above HTTP/1.1, holding connection keep-alives, buffering the full request before forwarding — which absorbs single-byte drip and fragmented-framing attacks, stated from the nginx documentation with the 414/400/408 mechanics), the Unix-socket lockdown story, an always-read-the-latest-documentation statement, and the author's opinion on conservative edge choices. The ext/http README carries the annotated nginx settings block with explicit-default comments on every restated default.
- Worked, tested edge examples under `ext/http/edge/`: the realworld-lua demo app behind nginx, OpenResty, Traefik, and Envoy — each built from one shared Debian base image and proven by a conformance suite (happy paths, oversize body, oversized header section, drip-feed), all four edges passing 8/8. The key delta made concrete: full-request buffering is nginx's default (opt-out); Traefik and Envoy stream by default and the buffering must be installed explicitly.

### The fuzz gate and the verified hardening (0.18.2)

- The HTTP parser is proven by a fuzz gate, not just by fixtures. The seeded corpus fuzzer over `read_request` grew structure-aware mutators (method, version, Content-Length value, and header-name token rewrites) alongside the byte-level mutators. The gate asserts rejection-site coverage: every rejection records the parser's error message, and the full reachable-site set must fire across the seeded runs - an uncovered site is a corpus gap, not a success. Cap-boundary fixtures are generated from the live caps values: a request at each cap parses, one byte past rejects with the documented status (request line 414, header section 431, body 413). A differential classifier - an independent, minimal reimplementation of the framing contract sharing no code with the parser - replays the corpus and the fixtures; a classification disagreement between it and the parser is the finding. The committed corpus never shrinks: the gate pins a floor on the seed count.
- A nightly fuzz leg explores beyond the fixed per-push budget: a scheduled workflow builds the ASan + easy-memory instrumented runtime and runs the fuzz driver through it with a wall-clock seed (printed for deterministic replay) and a 50000-iteration budget, so oversize allocations and RSS misbehaviour count as findings. The per-push gate stays fixed-budget and deterministic.
- CI proves the release hardening flags on every platform instead of only applying them. A new `xmake verify-hardening` task asserts on the built release binaries what the security runbook previously documented as manual commands only: on Linux, `lunet-run` is PIE (`ET_DYN`), references `__stack_chk_fail`, and carries fortified `__*_chk` symbols; on macOS, the PIE flag and the stack-protector reference; on Windows, DYNAMICBASE and the `/GS` security cookie (dumpbin via vswhere). Every shipped shared module - the core runtime, the SDK library, sqlite3, mysql, postgres, httpc - is checked for the stack protector. The build workflow runs the task on all four platform legs right after the build; a missing flag fails the build.
