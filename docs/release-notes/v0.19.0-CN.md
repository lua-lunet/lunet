0.19 系列以完整的 Windows 发布对等能力开场：Windows 归档现在包含其他平台
所包含的每一个扩展模块，并且 Windows 上的 httpc 客户端可以正常工作。

## 亮点

### Windows 发布对等能力

- Windows 归档现在包含 Unix 与 macOS 归档所包含的一切：`lnt_shared.lua` +
  `lnt_shared.dll`、`jsonic.lua` + `dkjson` + `lunet_jsonic.dll`，以及
  `http_caps.lua`。lnt_shared 已移植到 Windows：其共享内存区域由页面文件
  分区支撑（`CreateFileMappingA`/`MapViewOfFile`），因此该 cdylib 在三个
  平台上都能构建并运行，且其 crate 自身的测试套件在 CI 的 Windows 上运行。
- 扩展加载器 Lua 文件（`jsonic.lua`、`lnt_shared.lua`、`paxe.lua`、
  `sodium.lua`）已处理 Windows cdylib 命名（`.dll` 不带 `lib` 前缀），并能
  拆分包含反斜杠的搜索路径；此前这会让 Windows 加载器静默地无法加载。
- Windows 打包现在是被验证的，而不是被假定的：CI 会检查每个打包归档中
  必需的扩展文件，并通过反斜杠 `package.path` 运行 `lunet-run.exe` 执行
  lnt_shared、jsonic、paxe 与 sodium 的脚本。

### Windows 上的 httpc

- `httpc.request` 在 Windows 上不再挂起。以 DLL 形式加载的扩展模块携带
  自己的 libuv 副本，因此其 `uv_default_loop()` 是宿主 `uv_run` 永远不会
  轮询的第二个循环实例：请求在线程池上完成了，但完成回调从未被派发，
  Lua 协程因此永远等待。现在运行时通过 Lua 注册表把它的事件循环交给扩展
  模块，`httpc.request` 在该循环上排队工作；详见 CONTRIBUTING-INTERNALS。
- httpc 回环冒烟测试现在还在 HEAD 用例之前覆盖：一次普通 GET、一次
  `file://` GET（无套接字的完整 worker/curl/完成流水线），以及一次异步
  `lunet.fs` 读取（与 httpc 相同的线程池机制），因此即使 httpc 探针挂起，
  fs 探针也能捕获完成派发中的回归。
