- **Transactions, with the pinning trap closed** (#119): each driver now ships a transaction wrapper — `lunet.sqlite3_tx`, `lunet.postgres_tx`, `lunet.mysql_tx`. A transaction belongs to a *connection*, not a coroutine, so a pool that checks a connection out per call and returns it afterwards puts `BEGIN`, the work and `COMMIT` on three different sessions and commits nothing, silently. `transaction(conn, fn)` takes the connection and holds it for the whole unit. Return non-nil to commit; return `nil, reason` or raise to roll back; `err.poisoned` marks a connection whose session state is unknown and must be closed rather than pooled. Three separate modules rather than one shared helper, because an application builds one driver and the three databases genuinely differ — see the new README in each driver folder for the per-driver traps and the verification methodology.
- **Embeddable SDK in every release** (#117): new per-OS SDK archives (`lunet-<os>-sdk.tar.gz` / `-sdk.zip`) ship a linkable static core (`liblunet-static.a` / `lunet-static.lib`), the public C header (`include/lunet.h`: `lunet_runtime_init` / `run_file` / `run_embedded` / `shutdown`), the `LUNETPK1` embed-blob generator, and a worked example with exact per-OS link commands. Ship your own `main()` + Lunet + your Lua app as one self-contained `<app>-<os>-<arch>.run` executable — no xmake, no exploded script tree. CI verifies each packaged SDK by extracting, compiling, and running the example on all three OSes.
- **OpenAlex SSE MCP example** (`examples/mcp_openalex_sse/`): the canonical tiny localhost MCP server — SSE transport, JSON-RPC, three tools (`openalex_search_works`, `openalex_get_work`, `openalex_search_authors`) backed by the free OpenAlex scholarly API via `lunet.httpc` (libcurl). No database, no filesystem state, loopback only; API key from `.env`.
- **Three developer experiences documented**: run Lua on release binaries (no toolchain), package a self-contained appliance with the SDK, or hack the core from source with xmake — see the reworked README and the new [The Talos, Ethos and 無為 of Lunet](docs/PHILOSOPHY.md).
- **Per-release notes**: release bodies are now generated per tag instead of sharing one static template. Minor releases list their `feat:` commits; patch releases carry their line's highlights forward and list only their own fixes. The seven earlier releases that had been published carrying v0.2.0's highlights have been corrected.

### Breaking

- **`db.escape` is removed** from all three drivers (`lunet.sqlite3`, `lunet.mysql`, `lunet.postgres`). All three implementations were hand-rolled `string.gsub` passes rather than the driver's own escaping API, and none could have used that API: `db.escape` took only a string, while `PQescapeStringConn` and `mysql_real_escape_string` both need a connection to be charset-aware. The MySQL one emitted backslash escapes, which are wrong under `NO_BACKSLASH_ESCAPES`. Nothing in the tree used it. Bind parameters instead — `db.query`/`db.exec` pass them to `sqlite3_bind_*` / `mysql_stmt_bind_param` / `PQexecParams`, which is both safe and the only supported path.

### Fixes

- **sqlite3 silently discarded bound parameters** on `db.query` and `db.exec`. Only `db.query_params`/`db.exec_params` called into the binder, so `db.exec(conn, "INSERT INTO t (a,b) VALUES (?,?)", "x", 1)` inserted `(NULL, NULL)` and reported success. Silent data loss, not a crash. The postgres and mysql drivers already bound parameters on all four entry points; sqlite3 was the odd one out.
- **Extension Lua loaders now resolve from anywhere.** The runtime configured `package.cpath` but not `package.path`, so a Lua loader shipped beside its binary under `lunet/` was only reachable when the process happened to be started from the archive root. This affected `lunet.lnt_shared` and `lunet.jsonic` as well as the new `*_tx` modules.
- **macOS builds are no longer broken.** The build job ran `timeout`, which does not exist on macOS, so every macOS leg failed with exit 127 — and `fail-fast` then cancelled the Windows leg, meaning a red macOS build also meant no Windows result at all.
- **The Windows SDK verification now actually runs.** It had two defects that were unreachable while macOS was failing first: the example was linked against the static CRT while `lunet-static.lib` and the vcpkg triplet are dynamic (six `LNK2019` unresolved `__imp_` CRT symbols), and once linked it could not find `lua51.dll` / `uv.dll` / `zlib1.dll` at run time.
- `main` now has branch protection with required status checks, so a pull request can no longer merge without a CI signal.
