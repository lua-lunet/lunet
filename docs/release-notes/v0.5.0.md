- **Embeddable SDK in every release** (#117): new per-OS SDK archives (`lunet-<os>-sdk.tar.gz` / `-sdk.zip`) ship a linkable static core (`liblunet-static.a` / `lunet-static.lib`), the public C header (`include/lunet.h`: `lunet_runtime_init` / `run_file` / `run_embedded` / `shutdown`), the `LUNETPK1` embed-blob generator, and a worked example with exact per-OS link commands. Ship your own `main()` + Lunet + your Lua app as one self-contained `<app>-<os>-<arch>.run` executable — no xmake, no exploded script tree. CI verifies each packaged SDK by extracting, compiling, and running the example on all three OSes.
- **OpenAlex SSE MCP example** (`examples/mcp_openalex_sse/`): the canonical tiny localhost MCP server — SSE transport, JSON-RPC, three tools (`openalex_search_works`, `openalex_get_work`, `openalex_search_authors`) backed by the free OpenAlex scholarly API via `lunet.httpc` (libcurl). No database, no filesystem state, loopback only; API key from `.env`.
- **Three developer experiences documented**: run Lua on release binaries (no toolchain), package a self-contained appliance with the SDK, or hack the core from source with xmake — see the reworked README and the new [The Talos, Ethos and 無為 of Lunet](docs/PHILOSOPHY.md).
- **Per-release notes**: release bodies are now generated per tag instead of sharing one static template. Minor releases list their `feat:` commits; patch releases carry their line's highlights forward and list only their own fixes.

### Breaking

- **`db.escape` is removed** from all three drivers (`lunet.sqlite3`, `lunet.mysql`, `lunet.postgres`). All three implementations were hand-rolled `string.gsub` passes that were not connection- or charset-aware, and the MySQL one emitted backslash escapes that are wrong under `NO_BACKSLASH_ESCAPES`. Nothing in the tree used it. Bind parameters instead — `db.query`/`db.exec` pass them to `sqlite3_bind_*` / `mysql_stmt_bind_param` / `PQexecParams`, which is both safe and the only supported path. The README now documents transactions explicitly, including that a parameterised statement must be a single command and that a transaction belongs to the connection handle rather than the coroutine.
