- **DevX 贡献者本地快速搭建** (#123)：一条命令 —— `make init` —— 即可把一台全新的机器配置成完整的贡献者环境。它委托给 `contributing/` 下的各操作系统脚本（`macos`、`debian`、`windows`），安装工具链（编译器、libuv、LuaJIT、zlib、sqlite3、libsodium、curl、postgres/mysql 客户端头文件）以及 QA 套件（luarocks、busted、luacheck）。CI 现在也通过完全相同的 `contributing/deps/*` 脚本安装依赖，因此开发者本地运行的内容与构建运行器运行的内容一致 —— 从机制上保证开发/CI 一致性。整个流程已在 docker 内的真实 `debian:trixie` 镜像上验证通过。
- **CI 新增 `lua-qa` 门禁**：luacheck 和 C 命名规范 lint 现在作为独立的必需检查项，在每次 push 和 pull request 时运行，与构建矩阵、embed-scripts 冒烟测试和 easy-memory 检查并列。`main` 分支保护已要求该项。
- **Lint 归零**：`xmake check` 从 331 条 luacheck 警告降至 0，`.luacheckrc` 按目录校准（生成的 `types/` 目录按设计忽略 212 类"未使用参数"警告）。
- **工具链锁定**：xmake 通过 `.mise.toml` 锁定为 3.0.8，CI 的 `setup-xmake` 步骤使用同一锁定版本，本地与运行器构建使用完全相同的构建工具版本。

### 修复

- **发布说明生成器不再把 xmake 的 `{ }` 回显混入发布正文。** `xmake lua` 会把 ANSI 花括号装饰回显到 stdout；生成器现在会将其剥离，发布内容为干净的 markdown。
- **`xmake check` 能找到可用的 luacheck。** 之前当 PATH 上存在多个 luacheck 二进制时会选中一个损坏的封装；现在优先使用基于 LuaJIT 的安装。
- **CI 的 luarocks 安装在运行器用户对系统目录无写权限时使用 `sudo`**，修复了共享运行器上的 Linux 依赖安装步骤。
