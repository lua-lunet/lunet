- **DevX fast local setup for contributing** (#123): one command — `make init` — takes a fresh machine to a fully provisioned contributor environment. It delegates to per-OS scripts under `contributing/` (`macos`, `debian`, `windows`) that install the toolchain (compiler, libuv, LuaJIT, zlib, sqlite3, libsodium, curl, postgres/mysql client headers) plus the QA stack (luarocks, busted, luacheck). CI now installs its dependencies through the very same `contributing/deps/*` scripts, so what a developer runs locally is what the build runners run — dev/CI parity by construction, and the whole flow is verified on a real `debian:trixie` image in docker.
- **`lua-qa` gate in CI**: luacheck and the C naming-convention lint now run as a dedicated required check on every push and pull request, alongside the build matrix, the embed-scripts smoke tests, and the easy-memory legs. Branch protection on `main` requires it.
- **Lint at zero**: `xmake check` went from 331 luacheck warnings to 0, with `.luacheckrc` calibrated per directory (the generated `types/` tree ignores the 212 "unused argument" class by design).
- **Toolchain pinned**: xmake is pinned to 3.0.8 via `.mise.toml` and the same pin in CI's `setup-xmake` steps, so local and runner builds use the identical build-tool release.

### Fixes

- **The release-notes generator no longer leaks xmake's `{ }` echo into release bodies.** `xmake lua` echoes its ANSI brace decoration to stdout; the generator now strips it, so published notes are clean markdown.
- **`xmake check` finds a working luacheck.** It previously picked up a broken wrapper when several luacheck binaries were on PATH; it now prefers the LuaJIT-backed install.
- **CI luarocks installs use `sudo` where the runner user lacks write access** to the system tree, unbreaking the Linux dep-install steps on shared runners.
