- **已接受的 TCP 连接不再会丢失或被搁置**:修复了监听/接受路径上的四个缺陷。(1) 如果 accept 等待者的注册表槽位曾经不是协程,已被接受的连接会被静默丢弃且等待者永远不会被唤醒——现在该连接会被排入队列等待后续的 `socket.accept`,并且该异常情况会被记录到日志。(2) `socket.close(listener)` 现在会以 `nil, "listener closed"` 唤醒驻留的 acceptor,并关闭那些已被接受但从未交付的连接,而不是泄漏它们。(3) 连接回调中的内存不足/句柄初始化失败路径现在会消费掉待处理的连接(libuv 在 `uv_accept` 消费之前会停止轮询监听器),并且在灾难性失败时会关闭监听器并唤醒 acceptor——而不是让监听器卡死而客户端却看到 `ESTABLISHED`。(4) `socket.accept` / `socket.read` / `socket.write` 会拒绝在正在关闭的句柄上驻留,而不是永远让出。回归测试:`test/socket_close_wakeup.lua` 和 `test/accept_udp_concurrent.lua`,均已接入 `xmake stress`。
- **套接字句柄现在是完整 userdata,而不是 lightuserdata**:此修复解决了 accept/connect 路径上的一个 OOM 安全问题(lightuserdata 的压栈操作本身不会失败,但它所代表的分配操作可能失败),并带来两个用户可见的变化——`tostring(handle)` 现在会为每个句柄打印一个独立的 userdata 地址,而不是旧的 lightuserdata 形式;并且每个句柄现在都带有一个含 `__gc` 元方法的元表。请注意,GC**不会**关闭底层的 socket/fd;必须显式调用 `socket.close()` 才能避免泄漏。
- **owning-`lua_State*` 的生命周期划分现在会对已知易错模式做 lint 检查**:异步句柄上下文按生命周期和职责命名其状态字段——长生命周期的 libuv 句柄使用 `owner_L` 作为其 owning state(通常来自 `default_luaL()`,可使用惯常的 fallback 形式,被接受的客户端也可从监听器继承),操作级上下文使用 `waiter_L`(调用协程,在操作期间由 coref 锚定)。`xmake lint` 规则 4/5 会拒绝遗留的 `->L = L` / `->co = L` 模式,以及直接的 `owner_L = L` / `owner_L = co` 赋值。`src/signal.c` 正是该缺陷类别的一个现存实例,已修复。
- **`signal.wait` 语义已写入文档**:它是一次性的——第一个匹配的信号会唤醒等待者,但**不会**终止进程(第一个 `SIGTERM` 是被投递给协程,而不是致命的)。如果希望进程停止,请在处理程序中退出。
- **项目本地的可验证运行时安装**:每个发布版本现在都会随归档附带一个自动生成的 `lunet_fetch_release_<tag>.lua` 辅助脚本。在使用方项目中用任意 Lua 5.1+ 解释器运行它,它会检测主机操作系统/架构,从本发布版本下载对应的官方二进制归档,并在解压*之前*根据发布元数据中的 digest 校验归档的 SHA-256(不匹配则直接失败),然后安装到按版本划分的项目本地目录:

  ```text
  .lunet/<tag>/lunet-run
  .lunet/<tag>/types/
  ```

  安装是原子的(先在同级临时目录中暂存,只有 digest 和目录布局检查全部通过后才移动到位)且幂等的(有效的既有安装直接复用,不产生网络请求;不完整的安装会被修复)。进度信息输出到 stderr;stdout 的最后一行是运行时路径,因此 Makefile 可以锁定确切的运行时:`LUNET_RUN := $(shell lua lunet_fetch_release_<tag>.lua)` → `.lunet/<tag>/lunet-run path/to/app.lua`。不受支持的主机会明确报错,而不是回退到 `PATH` 上碰巧存在的某个 `lunet-run`。
- **发布自动化**:辅助脚本由发布工作流按标签从 `bin/lunet_fetch_release.lua` 模板渲染生成,因此今后的每个发布版本都会自动携带名称正确、版本锁定正确的获取脚本,无需任何手动步骤。同样经过测试的 v0.7.2 脚本(`lunet_fetch_release_v0.7.2.lua`)已补充附加到 v0.7.2 发布版本;发布说明生成器也不会再执行出现在精选说明文本中的 `$(shell ...)` 序列。
