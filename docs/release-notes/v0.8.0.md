- **Accepted TCP connections can no longer be lost or stranded** (#145): four defects in the listener/accept path are fixed. (1) If the accept waiter's registry slot was ever not a coroutine, the already-accepted connection was silently dropped and the waiter never resumed — the connection is now queued for a later `socket.accept` and the corruption is logged. (2) `socket.close(listener)` now wakes a parked acceptor with `nil, "listener closed"` and closes accepted-but-undelivered connections instead of leaking them. (3) Out-of-memory / handle-init failure paths in the connection callback now consume the pending connection (libuv stops polling a listener until `uv_accept` consumes it) and, on catastrophic failure, close the listener while waking the acceptor — instead of wedging the listener while clients saw `ESTABLISHED`. (4) `socket.accept` / `socket.read` refuse to park on a closing handle instead of yielding forever. Regression tests: `test/socket_close_wakeup.lua` and `test/accept_udp_concurrent.lua`, both wired into `xmake stress`.
- **The owning-`lua_State*` invariant is now machine-enforced**: async handle contexts name their state field by lifetime — `owner_L` for long-lived libuv handles (sourced from `default_luaL()`, inherited by accepted clients) versus `waiter_L` for operation-scoped contexts (calling coroutine, anchored by a coref for the op). `xmake lint` rules 4/5 reject legacy `->L = L` / `->co = L` assignments and any `owner_L` not sourced from `default_luaL()` or another `owner_L`. `src/signal.c` was a live instance of the defect class and is fixed.
- **`signal.wait` semantics documented**: it is one-shot — the first matching signal resumes the waiter and does **not** terminate the process (the first `SIGTERM` is delivered, not fatal). Exit from the handler if you want the process to stop.
- **Project-local verified runtime installs** (#143): every release now ships a generated `lunet_fetch_release_<tag>.lua` helper alongside the archives. Run it from a consumer project with any Lua 5.1+ interpreter and it detects the host OS/architecture, downloads the matching official binary archive from this release, verifies the archive's SHA-256 against the release metadata digest *before* extraction (failing closed on mismatch), and installs into a versioned project-local layout:

  ```text
  .lunet/<tag>/lunet-run
  .lunet/<tag>/types/
  ```

  Installs are atomic (staged in a sibling directory, moved into place only after digest and layout checks pass) and idempotent (a valid existing install is reused without network I/O; an incomplete one is repaired). Progress goes to stderr; stdout's last line is the runtime path, so a Makefile can pin the exact runtime: `LUNET_RUN := $(shell lua lunet_fetch_release_<tag>.lua)` → `.lunet/<tag>/lunet-run path/to/app.lua`. Unsupported hosts fail clearly rather than falling back to whatever `lunet-run` is on `PATH`.
- **Release automation**: the helper is rendered per tag by the publish workflow from the `bin/lunet_fetch_release.lua` template, so every future release carries a correctly named, correctly pinned fetcher with no manual step. The same tested script for v0.7.2 (`lunet_fetch_release_v0.7.2.lua`) has been retroactively attached to the v0.7.2 release, and the release-notes generator no longer executes `$(shell ...)` sequences that appear inside curated notes.
