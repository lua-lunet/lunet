- **PAXE is now a Rust extension backed by paxe-core v0.1.0 — breaking change.** The old C implementation (`src/paxe.c`) is deleted: its wire format was never the real PAXE wire format and its documented overheads were wrong (36/82 hard-coded; the true values are 37/97, now read from the library at load time so they cannot drift). The protocol core lives in the independently tested [`paxe-core`](https://github.com/lua-lunet/paxe-core) crate — pinned by git tag in `ext/paxe/Cargo.toml`, fetched over SSH for developers and over token-authenticated HTTPS in CI — and lunet ships a thin C-ABI cdylib (`ext/paxe`) plus a pure-Lua FFI loader (`lunet/paxe.lua`, same loading model as `lunet.jsonic`). The extension stays pure opt-in: nothing is linked into `lunet-run`, and libsodium is linked statically so release archives remain self-contained.
- **New `lunet.paxe` Lua API**: `set_local_id(node_id)` configures the node's identity once; keys are installed per link and epoch with `keystore_set(peer, epoch, key)` / `keystore_retire` / `keystore_clear`; `seal(payload, to_id, channel)` always produces a **standard** one-recipient frame (there is no size-based mode selection in the C ABI); `open(frame)` returns the payload plus the authenticated `fromId`, channel and mode, and can also open reusable-DEK fanout frames sealed by a Rust host. Every frame-level failure collapses to one opaque `nil, "lunet.paxe: frame rejected"` — a receiver that explains why a forgery failed is a decryption oracle — and the reason survives only in the 13 cumulative `stats()` counters (measure deltas, never absolute values). `paxe.protect(sock, {peer=…, channel=…})` opts an individual `lunet.udp` socket into sealing/opening, wired entirely in the Lua layer (`src/udp.c` untouched); there is deliberately no process-global enable switch. Malformed arguments raise; operational failures return `nil, message`.
- **Security posture**: keys live in guarded, `mlock`ed, zeroed-on-drop libsodium allocations owned by Rust and never cross the FFI outward; `paxe.init()` requires the AES-256-GCM hardware path (no software fallback), disables process core dumps by default (`LUNET_PAXE_ALLOW_CORE_DUMPS=1` is the documented debugging opt-out), and registers an `atexit` keystore-erasure hook. The crate is built `panic = "abort"` with a no-panic-on-any-input discipline, validated at both sides of the FFI.
- **Wire format and docs**: the normative contract is paxe-core's PAXE.md; the lunet integration reference moved to `docs/PAXE.md` / `docs/PAXE-CN.md` and was rewritten for the new implementation — and because it now lives under `docs/`, the release workflow's default-copy rule finally bundles it into the binary archives (the packaging gap that shipped the module with no reachable protocol documentation is fixed). Tests: `spec/paxe_spec.lua` behavioural suite (runs in `xmake test`), `test/smoke_paxe.lua`, a two-process protected-UDP end-to-end (`test/run_paxe_udp_e2e.sh`), and rewritten `examples/06_paxe_encryption.lua` / `examples/07_paxe_stress.lua`.
- **Migration**: there is no on-wire or API compatibility with the deleted C module. Applications using `paxe.init`/`set_enabled`/`keystore_set(key_id, …)`/`encrypt`/`try_decrypt` must move to the API above; the old global-enable model is replaced by per-socket `paxe.protect`. See `docs/PAXE.md` for the full reference.
